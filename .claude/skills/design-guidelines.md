# デザインガイドライン

「AIが作ったデザインに見えない」プロフェッショナルな UI を実現するためのルール集。
引数に `check` が指定された場合は、既存ページのデザイン違反を検出・報告する。

---

## AIっぽいデザインの特徴（= 避けるべきパターン）

- すべての要素が均一なサイズ・余白・角丸で並んでいる
- 視覚的な重み付けがなく、全部同じ重要度に見える
- ホバーやトランジションがない静的な画面
- 「アイコン + タイトル + 説明文」の繰り返しカードレイアウト
- 情報密度が低くスカスカ
- ステータスが英語の生テキスト
- browser の `alert()` / `confirm()` を使っている
- ローディングが Spinner だけ

---

## 1. 視覚的ヒエラルキー

### 基本的な考え方

ページ内の情報には必ず優先度がある。テキストのサイズ・ウェイト・色の3軸で「何が最も重要か」を瞬時に伝える。

### ルール

- ページには最大 **3段階** のテキスト階層を設ける（見出し / 本文 / 補足）
- 数値データ（KPI等）はラベルより **2段階以上大きい** textStyle を使う
- 補足テキストは `fg.muted` または `fg.subtle` で薄くする
- ラベルは `textStyle="xs"` + `fontWeight="medium"` + `textTransform="uppercase"` + `letterSpacing="wide"` で控えめに、数値は `textStyle="3xl"` 以上で大きく表示する

### やってはいけないこと

- すべてのテキストを同じサイズ・色で表示する
- 見出しと本文のサイズ差が1段階しかない
- KPIの数値とラベルが同じ大きさ

---

## 2. カード・コンテナ

### 基本的な考え方

カードは「面」で情報をグループ化する要素。border だけの平坦なカードはAI生成感が強い。shadow と hover で奥行きとインタラクティブ性を持たせる。

### ルール

- カードには必ず `shadow="xs"` 以上を付ける（border だけにしない）
- クリック可能なカードには `_hover` で shadow を1段階上げる + `cursor="pointer"`
- 主要カード（KPI、CTA）と補助カードで padding サイズを変える（主要: `p="6"`, 補助: `p="4"`）
- 重要なカードは `bg="colorPalette.subtle.bg"` で背景色をつけて差別化する
- グリッド配置では `minmax(280px, 1fr)` で最小幅を確保する
- `transition="all"` + `transitionDuration="normal"` でスムーズな状態変化を付ける

### やってはいけないこと

- 全カードを同一の `p="4" border rounded="l2"` で統一する
- shadow なしの border だけのカード
- hover 時に何も変化しないクリック可能要素

---

## 3. ナビゲーション

### 基本的な考え方

サイドバーナビゲーションは、ユーザーが「今どこにいるか」を常に把握できなければならない。テキストリンクだけでは不十分。

### ルール

- ナビゲーションリンクには必ず `lucide-react` のアイコンを付ける
- アクティブ状態は **3点セット** で表現する: `bg`（背景色）+ `fontWeight`（太字）+ `color`（アクセントカラー）
- ホバー状態は `_hover` で背景色を薄く変化させる
- `usePathname()` でアクティブ判定する
- ナビゲーション項目は配列で定義し、`icon` / `href` / `label` を持たせる

### やってはいけないこと

- `<Link>` の生テキストだけのナビゲーション
- アクティブ状態の視覚的な区別がない
- アイコンなしのテキストリンク一覧

---

## 4. ステータス表示

### 基本的な考え方

ステータスは色と形で「状態の意味」を直感的に伝える。生テキストでは視認性が悪く、英語のまま表示するとユーザーに不親切。

### ルール

- ステータスは必ず `Badge` コンポーネントで表示する
- ステータスごとの `colorPalette` マッピングは定数オブジェクトで定義する
- 色の使い分け: 肯定的 → `green`、中立/待機 → `blue` or `gray`、否定/警告 → `red`
- ステータスラベルは **日本語** にする
- ダッシュボードのステータス集計も Badge で表示する

### やってはいけないこと

- `{booking.status}` のように英語の生テキストで表示する
- ステータスごとの色分けなしにテキストだけで一覧表示する
- 色だけで区別する（ラベルテキストも必要）

---

## 5. テーブル・データ表示

### 基本的な考え方

テーブルの操作列は「ボタンに見える」必要がある。空状態は「何もない」ことを丁寧に伝える。

### 操作列の使い分け

| 操作の数 | パターン |
|---|---|
| 1〜2個 | `IconButton` + `Tooltip` で直接表示 |
| 3個以上 | `Menu`（MoreHorizontal アイコン）に格納 |

### 空状態の構成

空状態は **3層構造** で表示する:
1. **アイコン** — 状況を象徴する lucide-react アイコン（`color="fg.subtle"`、大きめ）
2. **メッセージ** — 何がないかを明確に（`fontWeight="medium"`、`color="fg.muted"`）
3. **補足** — 次のアクションや理由（`textStyle="sm"`、`color="fg.subtle"`）

### やってはいけないこと

- テーブル操作を `<Link>` のテキストリンクで表示する
- 空状態を `<Text>データはありません</Text>` の1行で済ませる
- ID列を全文表示する（先頭8文字 + `...` に省略するか Tooltip で全文表示）

---

## 6. ローディング

### 基本的な考え方

ローディング中もレイアウトを維持する。Spinner だけの画面はレイアウトシフトを引き起こし、体験が悪い。

### 使い分け

| 場面 | パターン |
|---|---|
| ページ全体の初回読み込み | `Skeleton` でコンテンツの形を予告する |
| テーブルの読み込み | テーブル構造を維持した Skeleton（ヘッダーは実テキスト、セルは Skeleton） |
| KPIカードの読み込み | カード枠を維持した Skeleton |
| ボタン内の非同期処理 | Button の `loading` / `loadingText` props |
| インライン部分更新 | `Spinner`（小さいサイズ） |

### ルール

- `loading.tsx` ファイルでも Skeleton ベースのローディングを定義する
- Skeleton の形状は実コンテンツの形に合わせる

### やってはいけないこと

- `if (isLoading) return <Spinner />;` でページ全体を Spinner にする
- ローディング中にレイアウトが崩れる・ジャンプする

---

## 7. 確認・フィードバック

### 基本的な考え方

破壊的操作は Dialog で確認し、結果は Toast で通知する。browser ネイティブダイアログは使わない。

### 使い分け

| 場面 | パターン |
|---|---|
| 破壊的操作（削除、キャンセル等） | `Dialog` で確認。破壊的ボタンは `colorPalette="red"` |
| 操作の成功通知 | `Toast`（`type: "success"` or `type: "info"`） |
| エラー通知 | `Toast`（`type: "error"`） |
| 入力バリデーション | `Field.ErrorText`（フォーム内インライン表示） |

### Dialog の構成

SmartHR の削除ダイアログパターンに準拠:
1. **タイトル** — 何をするかを明確に（例:「予約をキャンセルしますか？」）
2. **説明** — 影響範囲を伝える（例:「この操作は取り消せません。クライアントに通知メールが送信されます。」）
3. **操作ボタン** — 右寄せ。キャンセルボタン（`variant="outline"`）+ 実行ボタン

### やってはいけないこと

- `alert()` / `confirm()` / `prompt()` を使う
- 破壊的操作を確認なしで実行する
- エラーを `alert()` で表示する

---

## 8. 余白とリズム

### 基本的な考え方

余白はデザインの「句読点」。異なる種類のセクション間では余白を変えて、視覚的なリズムを作る。

### ルール

| 対象 | 余白 |
|---|---|
| セクション間（異種） | `mb="8"` ～ `mb="10"` |
| セクション内（見出し → コンテンツ） | `mb="3"` ～ `mb="4"` |
| カードグリッドの gap | `gap="4"` ～ `gap="6"` |
| テキストの行間補足 | `mt="1"` |

### ページヘッダーの構成

ページヘッダーは `justifyContent="space-between"` でタイトル（左）とアクション（右）を配置する:
- **左側**: 見出し（`textStyle="2xl" fontWeight="bold"`）+ 補足テキスト（`textStyle="sm" color="fg.muted"`）
- **右側**: 主要アクションボタン

### やってはいけないこと

- すべてのセクション間を同じ `mb="4"` で統一する
- ページヘッダーのタイトルとアクションボタンを縦並びにする

---

## 9. フォーム

### 基本的な考え方

フォームは「ラベル + 入力 + 補足」の3点セット。placeholder だけのフォームは不親切。

### ルール

- すべての入力フィールドに `Field.Label` を付ける
- 入力の目的が分かりにくいフィールドには `Field.HelperText` で補足する
- 必須フィールドには `Field.RequiredIndicator` で明示する
- 送信ボタンは `loading` prop でローディング状態を表示する
- フォームのセクションが多い場合は見出しで区切る

### やってはいけないこと

- placeholder だけでラベルのないフォーム
- 必須/任意の区別がないフォーム
- 送信中にボタンが無反応のまま

---

## 10. 補足情報（Tooltip）

### 基本的な考え方

Tooltip は「聞かれたら答える」補足情報。重要な情報は本文に書き、Tooltip は補助に留める。

### 必ず Tooltip を付ける場面

- `IconButton` — アイコンだけでは意味が伝わらない
- `truncate` で省略されたテキスト — 全文を Tooltip で表示
- 専門用語・略語 — 初見で意味が分からない可能性がある語
- ID列の省略表示 — 先頭8文字表示 + Tooltip で全文

### やってはいけないこと

- IconButton に Tooltip なしで配置する
- 重要な操作説明を Tooltip だけに書く（本文に書くべき）
- Tooltip の中に長文を入れる

## コンポーネント選択早見表

| 場面 | 使うコンポーネント |
|---|---|
| 操作ボタン | `Button`（variant で優先度を表現。Primary 相当は1画面に最大1つ） |
| アイコンだけの操作 | `IconButton` + `Tooltip`（セット必須） |
| ステータス表示 | `Badge`（colorPalette で色分け） |
| 操作が3つ以上 | `Menu`（MoreHorizontal アイコンで開く） |
| 破壊的操作の確認 | `Dialog` |
| 操作結果の通知 | `Toast` |
| ページ読み込み中 | `Skeleton` / `SkeletonCircle` / `SkeletonText` |
| ボタン内の読み込み | Button の `loading` prop |
| フォームフィールド | `Field.Root` > `Field.Label` + Input + `Field.HelperText` + `Field.ErrorText` |
| 補足情報 | `Tooltip` |

## デザイントークン早見表

| トークン | 値 |
|---|---|
| カラーパレット | `blue` / `green` / `red` / `gray` |
| セマンティックカラー | `fg.default` / `fg.muted` / `fg.subtle` / `border` / `error` |
| シャドウ | `xs` / `sm` / `md` / `lg` / `xl` / `2xl` / `inset` |
| 角丸 | `l1`（xs）/ `l2`（sm）/ `l3`（md） |
| テキストスタイル | `xs` ～ `7xl` / `label` |

## check モード

引数に `check` が指定された場合:

1. `src/app/` 配下の全ページ・レイアウト・コンポーネントをスキャンする
2. 以下の違反を検出する:
   - `alert()` / `confirm()` / `prompt()` の使用
   - ローディングが `<Spinner />` 単独返却になっている
   - ステータスが `Badge` ではなく生テキスト表示されている
   - テーブル操作列が `<Link>` や `<a>` のプレーンテキスト
   - ナビゲーションリンクにアイコンがない
   - ナビゲーションにアクティブ状態の表現がない
   - カードに `shadow` がない
   - カードやクリック要素に `_hover` がない
   - 空状態が `<Text>` 1行だけ
   - `IconButton` に `Tooltip` がない
   - ページヘッダーにタイトルとアクションの左右配置がない
3. 違反箇所をファイル名・行番号付きで報告する
4. 具体的な修正方針を提示する
